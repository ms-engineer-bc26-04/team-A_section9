# テスト設計書

## 1. 目的

本ドキュメントは、ENKATSUをMVPとして提出・デモできる状態にするため、テスト方針・確認対象・確認観点を整理するものです。

ENKATSUでは、未登録ユーザー・一般ユーザー・プレミアムユーザーで利用できる機能が異なるため、APIテストと画面確認の両面から、主要導線と認可ルールを確認します。

---

## 2. テスト方針

MVP提出前のテストでは、すべてのケースを網羅するのではなく、デモや主要機能に影響する範囲を優先して確認します。

優先して確認する観点は以下です。

1. 園一覧・園詳細が正常に取得できること
2. 認証が必要なAPIで未認証時に401が返ること
3. 一般ユーザー・プレミアムユーザーの権限制御が正しく行われること
4. お気に入り登録上限が正しく制御されること
5. 比較可能数がユーザー区分ごとに制御されること
6. Stripe Checkout / Webhook によりプレミアム化できること
7. README・docs・GitHub Actions・デモ導線に大きな不整合がないこと

## 6. Backend自動テスト方針

Backendでは、Vitest / Supertest を利用してAPIテストを作成します。

MVP提出前に優先する自動テストは以下です。

| ID     | テスト内容                                                                  | 優先度 |
| ------ | --------------------------------------------------------------------------- | ------ |
| BT-001 | `GET /api/v1/schools` 正常系                                                | Must   |
| BT-002 | `GET /api/v1/schools/:id` 正常系                                            | Must   |
| BT-003 | `GET /api/v1/schools/:id` 404                                               | Must   |
| BT-004 | `GET /api/v1/users/me` 未認証401                                            | Must   |
| BT-005 | `GET /api/v1/schools/compare` 未認証401                                     | Should |
| BT-006 | `POST /api/v1/users/me/favorites` 未認証401                                 | Should |
| BT-007 | `GET /api/v1/schools` Redisキャッシュ未登録時のDB取得・Redis保存            | Must   |
| BT-008 | `GET /api/v1/schools` Redisキャッシュ登録済み時のRedisレスポンス利用        | Must   |
| BT-009 | `GET /api/v1/schools` query params差分によるキャッシュキー分離              | Must   |
| BT-010 | `GET /api/v1/schools?sort=recommended` Redisキャッシュ対象外確認            | Must   |
| BT-011 | `GET /api/v1/schools` 認証ユーザー向けレスポンスのRedisキャッシュ対象外確認 | Must   |
| BT-012 | `GET /api/v1/schools` Redis読み取り失敗時のDBフォールバック確認             | Must   |
| BT-013 | `GET /api/v1/schools` Redis書き込み失敗時の正常レスポンス確認               | Must   |

認証済みユーザー・一般ユーザー・プレミアムユーザーの詳細なテストは、テストデータ準備の負荷が高い場合、手動確認または後続Issueで対応します。

Redisキャッシュの詳細なテストは、#150 で対応し、Redisクライアント・Supabase認証・ユーザー取得・お気に入り取得を必要に応じてmock化して確認します。

#150 では、`src/__tests__/api.test.ts` に以下のRedisキャッシュ関連テストを追加しています。

- キャッシュ未登録時にDB取得後Redisへ保存されること
- キャッシュ登録済みの場合にRedisの値が返ること
- query params が異なる場合に別キャッシュキーとして扱われること
- `sort=recommended` がキャッシュ対象外になること
- 認証ユーザー向けレスポンスがキャッシュ対象外になること
- Redis読み取り失敗時もDB取得へフォールバックすること
- Redis書き込み失敗時もAPIレスポンス自体は正常に返ること

実行コマンドは以下です。

```bash
npm run test
```

2026/06/30時点で、npm run test により src/**tests**/api.test.ts の12件がすべて成功していることを確認済みです。
