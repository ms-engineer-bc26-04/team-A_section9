# ENKATSU 要件定義書

## 1. サービス概要

### サービス名

ENKATSU
〜園活を円滑に〜

### サービス概要

ENKATSUは、共働き家庭・仕事復帰を控えた保護者向けに、保育園・こども園の「復職後の保護者負担」を検索・比較できるWebアプリケーションです。

既存の園検索サービスでは、所在地・定員・開園時間・延長保育の有無などの制度情報は確認できます。

一方で、実際に通わせるうえで重要な、

* 毎日の準備負担
* 平日に仕事を抜ける必要
* 延長保育を実際に利用している家庭の多さ
* 入園後に仕事と育児が無理なく回るか
* 連絡帳や欠席連絡など、日々のやり取りのしやすさ

といった情報は分かりにくい課題があります。

ENKATSUでは、園そのものの良し悪しではなく、保護者が復職後に感じる「生活負担」「時間負担」に焦点を当てて比較できるようにします。

また、ログイン済みユーザーはプロフィール情報の保存、お気に入り登録、比較機能、希望条件の保存を利用できます。

プロフィール編集画面では、お名前・郵便番号・住所を保存でき、郵便番号7桁入力時には住所検索APIを利用して住所を自動入力できます。

プレミアムユーザーは、3園比較・比較チャート・希望条件との一致表示・サポート情報の閲覧ができます。

さらにMVP追加機能として、園側管理者サイトを用意します。

園側管理者サイトでは、ENKATSU運営側から提供されたログインID・初期パスワードで保育園管理者がログインし、自園の情報を確認・編集できるようにします。

また、将来的に保護者から届いた問い合わせ・園見学予約を園側管理画面で確認できるようにするため、問い合わせ・見学予約に関するDB/API設計も追加します。

## 2. 解決したい課題

### 課題

既存サービスでは「入れる園」は探せても、「復職後に生活が回る園」は探しにくいです。

保護者は、園見学や問い合わせをしないと、以下のような情報を把握しづらい状況があります。

* 給食か弁当か
* 持ち物負担が多いか
* おむつや布団の家庭負担があるか
* 延長保育を実際に利用している家庭が多いか
* 平日行事や保護者会が多いか
* 連絡帳や欠席連絡の方法
* 園内習い事やアレルギー対応の有無

その結果、復職前の限られた時間で園を比較する負担が大きくなっています。

また、実際にサービスとして運用する場合、園情報をENKATSU運営側が電話などで収集・更新し続けるだけでは運用負荷が高くなります。

園情報が古くなると、保護者が正しい情報をもとに園を検討しづらくなります。

### 解決方法

ENKATSUでは、園情報を以下の2軸で整理します。

* 生活負担
* 時間負担

さらに、園選びの補助情報として、連絡帳・欠席連絡方法・園内習い事・アレルギー対応などを表示します。

ログイン済みユーザーは、お名前・郵便番号・住所などのプロフィール情報と希望条件を保存できます。

保存した住所は、ホーム画面のおすすめ表示でエリアに近い園を優先するために利用します。

保存した希望条件は、ホーム画面のおすすめ表示や、プレミアムユーザー向けの比較画面における一致項目ハイライトに利用します。

これにより、保護者が復職後の生活をイメージしながら、家庭に合う園を比較できるようにします。

また、園側管理者サイトを用意し、保育園管理者が自園の情報を確認・編集できるようにします。

園側が自園の情報を更新できるようにすることで、ENKATSU運営側だけが園情報を手動更新し続ける負担を減らし、情報の更新性を高めます。

問い合わせ・園見学予約については、MVPでは送信導線と管理画面上の表示枠を用意し、実データ連携は余力または後続対応とします。

## 3. ターゲットユーザー

### メインターゲット

仕事復帰を控えた共働き家庭・保護者。

特に、復職後も仕事を継続しながら、日々の育児・家事・送迎を無理なく回したい保護者を対象とします。

### サブターゲット

子どものケアや条件も確認しながら、保護者負担とのバランスを見て園を選びたい保護者。

### 園側ターゲット

ENKATSUに掲載される保育園・こども園の管理者。

園側管理者サイトでは、ENKATSU運営側から提供されたログインID・初期パスワードでログインし、自園の情報を確認・編集できます。

MVPでは、園側による自由なアカウント作成や、複数園を管理する法人アカウントは対象外とします。

## 4. 比較軸

### 4-1. 生活負担

日々の準備や家事に関わる負担です。

#### 比較項目

* 給食・弁当
* 持ち物負担
* 持ち物負担の具体的な内容
* おむつ対応
* 布団対応

#### 表示例

* 毎日給食
* 弁当あり
* 給食・弁当
* 持ち物負担：少なめ
* 持ち物負担の具体例：着替え・上履き程度
* おむつは園で廃棄
* おむつサブスク対応
* 布団は園で管理
* バスタオル持参

---

### 4-2. 時間負担

仕事との両立に関わる負担です。

#### 比較項目

* 延長保育利用時間
* 延長保育利用者の目安
* 平日行事の多さ
* 平日行事の具体的な内容
* 保護者会の負担
* 保護者会頻度

#### 表示例

* 延長保育利用時間：18:00〜20:00
* 延長保育利用者の目安：20人以上
* 平日行事：少なめ
* 平日行事の具体例：平日行事は少なめ
* 保護者会：少なめ
* 保護者会頻度：年に1回程度

延長保育については、制度の有無だけでなく、実際に利用している家庭がどの程度いるかを重視します。

---

### 4-3. サポート情報

生活負担・時間負担のメイン比較軸ではないものの、園選びの参考になる情報です。

#### 表示項目

* 連絡帳
* 欠席連絡方法
* 園内習い事
* アレルギー対応

#### 表示制限

未登録ユーザー・一般ユーザーには、サポート情報の項目名のみを表示し、内容はロック表示にします。

プレミアムユーザーは、サポート情報の内容まで閲覧できます。

## 5. 利用者区分

ENKATSUでは、利用者を以下の4区分で扱います。

| 区分 | 状態 | 内容 |
| --- | --- | --- |
| 未登録ユーザー | ログインしていない | アカウント登録をしていない、またはログインしていない保護者ユーザー |
| 一般ユーザー | ユーザー登録済み・無料 | Supabase Authで会員登録済みの無料ユーザー |
| プレミアムユーザー | ユーザー登録済み・有料 | Stripe決済によりプレミアムプランが有効なユーザー |
| 保育園管理者 | ENKATSU運営側が発行した園管理者アカウントでログイン | 自園情報の確認・編集、問い合わせ・見学予約一覧の確認枠を利用する園側ユーザー |

本ドキュメントでの「会員登録」は、無料の保護者ユーザー登録を指します。

プレミアムユーザーになるには、会員登録後にStripe Checkoutで決済を完了する必要があります。

アプリ内の会員区分は `users.plan_type` で補助的に管理し、実装上は `FREE` / `PAID` を使用します。

プレミアム判定は `subscriptions.status = ACTIVE` を正とします。

保育園管理者は、保護者向けの会員登録画面から自由に登録するのではなく、ENKATSU運営側が事前に作成・提供するアカウントでログインします。

#### 利用可能

* ホーム閲覧
* 園一覧閲覧
* 園詳細閲覧
* 保育園名・住所検索
* 条件検索
* プラン・料金画面閲覧

#### 利用不可

* お気に入り登録
* お気に入り管理
* 比較機能
* マイページ利用
* プロフィール編集
* プロフィール情報の保存
* 希望条件の保存
* プレミアム機能利用
* サポート情報の内容閲覧
* 園への問い合わせ送信
* 園見学予約送信
* 園側管理者サイト利用

未登録ユーザーは、園情報を1件ずつ確認できます。

お気に入りボタンを押した場合は、ログイン誘導モーダルを表示します。

未登録ユーザーがプレミアム登録ボタンを押した場合は、まず会員登録画面 `/register` へ遷移します。

会員登録後は一般ユーザーとして扱い、その後Stripe Checkoutで決済を完了するとプレミアムユーザーになります。

---

### 5-2. 一般ユーザー

#### 利用可能

* 園一覧閲覧
* 園詳細閲覧
* 保育園名・住所検索
* 条件検索
* お気に入り登録
* お気に入り解除
* お気に入り一覧閲覧
* 2園比較
* マイページ利用
* プロフィール編集
* プロフィール情報の保存
* 郵便番号による住所自動入力
* 希望条件の保存
* 園への問い合わせ送信導線
* 園見学予約送信導線
* ログアウト

#### 制限

* お気に入り登録は3園まで
* 比較は2園まで
* サポート情報の内容は閲覧不可
* 希望条件との一致表示は利用不可
* 3園比較は利用不可
* 園側管理者サイトは利用不可

一般ユーザーは、園情報の閲覧、お気に入り登録、2園比較ができます。

ただし、お気に入り登録数は3園までとし、上限に達した場合はプレミアムプランへの誘導を表示します。

一般ユーザーもプロフィール情報と希望条件を保存できますが、比較画面での一致項目ハイライトはプレミアムユーザーのみ利用できます。

園詳細ページから問い合わせ・園見学予約を送信できる導線はありますが、MVPでは送信内容のDB保存・園管理画面での実データ表示は余力または後続対応とします。

### 5-3. プレミアムユーザー

#### 利用可能

* 園一覧閲覧
* 園詳細閲覧
* 保育園名・住所検索
* 条件検索
* お気に入り登録
* お気に入り解除
* お気に入り一覧閲覧
* お気に入り無制限登録
* 3園比較
* 比較チャート閲覧
* 希望条件との一致表示
* サポート情報の内容閲覧
* マイページ利用
* プロフィール編集
* プロフィール情報の保存
* 郵便番号による住所自動入力
* 希望条件の保存
* 園への問い合わせ送信導線
* 園見学予約送信導線
* 一般プランへの変更導線
* ログアウト

#### 制限

* 園側管理者サイトは利用不可

プレミアムユーザーは、3つの園を同時に比較でき、比較チャートで園ごとの特徴を視覚的に確認できます。また、プロフィール編集画面で設定した希望条件と一致する項目を比較画面で確認できます。

また、一般ユーザーではロックされているサポート情報の内容を閲覧できます。

園詳細ページから問い合わせ・園見学予約を送信できる導線はありますが、MVPでは送信内容のDB保存・園管理画面での実データ表示は余力または後続対応とします。

---

### 5-4. 保育園管理者

#### 利用可能

* 保育園管理者ログイン
* 保育園管理者ログアウト
* 管理者ホーム画面の閲覧
* 自園情報の取得
* 自園情報の編集
* お問い合わせ一覧の表示枠閲覧
* 見学予約一覧の表示枠閲覧

#### 制限

* 園管理者アカウントは、園側が自由に作成できない
* ENKATSU運営側が事前に作成・提供したログインID・初期パスワードでログインする
* ログインIDは、Supabase Auth上のemailとして扱う
* 自園以外の園情報は取得・編集できない
* お問い合わせ一覧・見学予約一覧は、MVPではモック表示でもよい
* 問い合わせ・見学予約の実データ連携はMVP必須実装には含めない
* 保護者向けのプレミアム機能は利用対象外

保育園管理者は、ENKATSU運営側が事前に発行したアカウントで `/admin/login` からログインします。

認証にはSupabase Authを利用し、ログイン後は `school_admins` テーブルでログイン中ユーザーと管理対象の園を紐づけます。

## 6. 機能要件

### 6-1. ホーム画面

#### 対象

* 未登録ユーザー
* 一般ユーザー
* プレミアムユーザー

#### 機能

* サービス概要を表示する
* 保育園名・住所で検索できる
* 条件で検索できる
* 園一覧またはおすすめ園一覧を表示する
* 園詳細画面へ遷移できる
* お気に入り登録・解除ボタンを表示する

#### ログイン済みユーザー向けおすすめ表示

ログイン済みユーザーには、おすすめの園一覧を表示します。

おすすめ表示では、ユーザーの住所、希望条件、お気に入り傾向をもとに表示します。

ユーザーの住所は、プロフィール編集画面で保存された `users.address` の情報を利用します。

希望条件は、プロフィール編集画面から保存された `user_preferences` の情報を利用します。

MVPでは高度なレコメンド機能は作成せず、シンプルな条件一致数やお気に入り済み園の傾向をもとに並び替えます。

園一覧・検索結果・おすすめ表示では、Redisキャッシュを利用し、同一条件でのDBアクセスを減らします。

---

### 6-2. 園一覧・検索結果画面

#### 対象

* 未登録ユーザー
* 一般ユーザー
* プレミアムユーザー

#### 機能

* 園一覧を表示する
* 保育園名・住所で検索できる
* 条件検索ができる
* 検索条件を変更して再検索できる
* 園詳細画面へ遷移できる
* お気に入り登録・解除ができる

#### 検索条件

##### メイン検索

* 保育園名
* 住所
* エリア

##### 条件で検索

MVPでは、条件検索の「多い・少ない」はユーザーごとの主観ではなく、アプリ内の検索基準として定義します。

* 毎日給食
* おむつ園処理あり
* 布団負担少なめ
* 保護者会少なめ
* 延長保育利用者が多い
* 園内習い事あり
* アレルギー対応あり
* 平日行事少なめ

#### 条件検索の判定基準

| 画面表示 | バックエンド側の検索基準 |
| --- | --- |
| 毎日給食 | `mealType = SCHOOL_LUNCH` |
| おむつ園処理あり | `diaperSupport = "園で廃棄"` |
| 布団負担少なめ | `futonSupport = "園で管理"` |
| 保護者会少なめ | `parentAssociationLevel = LOW` |
| 延長保育利用者が多い | `extendedCareUsage = "20人以上"` |
| 園内習い事あり | `lessons IS NOT NULL` |
| アレルギー対応あり | `allergySupport IS NOT NULL` |
| 平日行事少なめ | `weekdayEventsLevel = LOW` |

フロントエンドでは、チェックボックス条件について以下のようなquery paramsを送信します。

| 画面表示 | query params |
| --- | --- |
| 毎日給食 | `mealType=SCHOOL_LUNCH` |
| おむつ園処理あり | `diaperSupport=true` |
| 布団負担少なめ | `futonSupport=true` |
| 保護者会少なめ | `parentAssociationLevel=LOW` |
| 延長保育利用者が多い | `extendedCareUsage=true` |
| 園内習い事あり | `lessons=true` |
| アレルギー対応あり | `allergySupport=true` |
| 平日行事少なめ | `weekdayEventsLevel=LOW` |

バックエンド側で、`true` は検索基準に応じた値に変換して絞り込みます。

#### 表示項目

* 園名
* 住所
* エリア
* 園種別
* 特徴タグ
* お気に入りボタン

#### お気に入り制限

* 未登録ユーザー：利用不可。ログイン誘導モーダルを表示する
* 一般ユーザー：3園まで登録可能
* プレミアムユーザー：無制限で登録可能

一般ユーザーが3園登録済みの状態で追加登録しようとした場合は、上限メッセージを表示し、プレミアムプランへ誘導します。

### 6-3. 園詳細画面

#### 対象

* 未登録ユーザー
* 一般ユーザー
* プレミアムユーザー

#### 表示項目

##### 基本情報

* 園名
* 住所
* エリア
* 園種別
* 園の特徴・補足説明

##### 生活負担

* 給食・弁当
* 持ち物負担
* 持ち物負担の具体的な内容
* おむつ対応
* 布団対応

##### 時間負担

* 延長保育利用時間
* 延長保育利用者の目安
* 平日行事の多さ
* 平日行事の具体的な内容
* 保護者会の負担
* 保護者会頻度

##### サポート情報

* 連絡帳
* 欠席連絡方法
* 園内習い事
* アレルギー対応

#### 表示用テキスト項目

園詳細画面では、画面表示でそのまま使える情報として、以下の表示用テキスト項目を利用します。

* 持ち物負担の具体的な内容
* 平日行事の具体的な内容
* 保護者会頻度

これらは、DB上では以下のカラムとして管理します。

| 画面表示 | DBカラム |
| --- | --- |
| 持ち物負担の具体的な内容 | `item_burden_detail` |
| 平日行事の具体的な内容 | `weekday_events` |
| 保護者会頻度 | `parent_association_frequency` |

#### サポート情報の表示制限

未登録ユーザー・一般ユーザーには、サポート情報の項目名のみを表示し、値の部分はロック表示にします。

プレミアムユーザーは、サポート情報の内容まで閲覧できます。

#### 機能

* 園情報を閲覧できる
* お気に入り登録・解除ができる
* 問い合わせ送信導線を表示する
* 園見学予約送信導線を表示する
* 存在しないIDの場合は404画面を表示する

#### 問い合わせ・園見学予約について

フロント側では、ログイン済みユーザーが園詳細ページから問い合わせ・園見学予約を送信できる画面導線を用意します。

MVPでは、送信内容をDBに保存し、園管理画面で実データとして表示する処理は必須対象外とします。

### 6-5. 比較画面

#### 対象

#### 制限

#### 比較項目

* 延長保育利用時間

* 平日行事の具体的な内容

| 比較項目 | DBカラム |
| --- | --- |

MVPでは、厳密なスコアリングやAI分析ではなく、登録済みの園データと希望条件の一致状況をもとに、ユーザーが違いを把握しやすくするための補助表示として扱います。

一般ユーザーには比較チャートを表示せず、プレミアムプランへの誘導を表示します。

#### プレミアム機能

プレミアムユーザーは、プロフィール編集画面で設定した希望条件と一致する項目が比較画面でハイライト表示されます。

希望条件は `user_preferences` に保存された情報を利用します。

MVPでは、希望条件との一致表示はプレミアムユーザーのみ利用できます。

希望条件が未設定の場合は、一致項目ハイライトは表示しません。

### 6-6. ログイン / 会員登録

#### 機能

* 会員登録できる
* ログインできる
* ログアウトできる

#### 認証方式

Supabase Authを使用します。

#### 会員登録時の扱い

ENKATSUにおける会員登録は、無料の保護者ユーザー登録を指します。

会員登録後は、一般ユーザーとして扱います。

Supabase Authで会員登録した後、アプリ側の `users` テーブルにもユーザー情報を作成します。

MVPでは、ログイン後に `GET /users/me` を実行したタイミングで、Supabase Auth上のユーザーは存在するがアプリ側の `users` レコードが存在しない場合、バックエンド側で一般ユーザーとして自動作成します。

作成時の初期値は以下とします。

* `id`：アプリ内ユーザーIDとしてUUIDを自動生成
* `supabase_user_id`：Supabase Auth User ID
* `email`：Supabase Authのメールアドレス
* `name`：未登録の場合は `null`
* `postal_code`：未登録の場合は `null`
* `address`：未登録の場合は `null`
* `plan_type`：`FREE`

プレミアムユーザーへの変更は、Stripe Checkout完了後、Webhookにより `subscriptions.status = ACTIVE` に更新された場合に行います。

### 6-8. プロフィール編集画面

#### 対象

* 一般ユーザー

未登録ユーザーがアクセスした場合は、ログイン画面へ遷移します。

#### 機能

* お名前を保存できる
* 郵便番号を保存できる

* 郵便番号7桁入力時に住所を自動入力できる
* 希望条件を保存できる
* 保存後、マイページへ戻ることができる

#### プロフィール情報

ユーザーは、以下のプロフィール情報を設定できます。

| 項目 | 内容 | 保存先 |
| --- | --- | --- |
| お名前 | ユーザーの表示名・お名前 | `users.name` |
| 郵便番号 | ハイフンなし7桁の郵便番号 | `users.postal_code` |
| 住所 | 郵便番号検索APIで自動入力、または手入力 | `users.address` |

#### 住所自動入力

郵便番号7桁入力時に、バックエンドの住所検索APIを利用して住所を自動入力します。

住所検索APIは住所自動入力用であり、DB保存は行いません。

住所の保存は、プロフィール情報保存時に行います。

```txt
GET /api/v1/address/search?zipcode=1234567
```

#### プロフィール情報の保存先

お名前・郵便番号・住所は `users` テーブルに保存します。

郵便番号はハイフンなし7桁で保存します。

保存・更新は以下のAPIで行います。

```txt
PUT /api/v1/users/me
```

#### 希望条件

ユーザーは、生活負担・時間負担・補助情報に関する希望条件を設定できます。

##### 生活負担

* 毎日給食
* 持ち物負担が少ない
* おむつは園で処理してほしい
* 布団負担が少ない

##### 時間負担

* 延長保育を利用したい
* 平日行事が少ない
* 保護者会が少ない

##### 補助情報

* 園内習い事あり
* アレルギー対応あり

#### 希望条件の保存先

希望条件は `user_preferences` テーブルに保存します。

1ユーザーにつき希望条件は0件または1件とし、未設定の場合は希望条件レコードを持たない状態とします。

希望条件が未設定の場合、APIでは `preference: null` を返します。

保存する希望条件は以下です。

* 希望する給食・弁当区分
* 希望する持ち物負担レベル
* 希望するおむつ対応
* 希望する布団対応
* 希望する延長保育条件
* 園内習い事ありを希望するか
* アレルギー対応ありを希望するか
* 希望する平日行事負担レベル
* 希望する保護者会負担レベル

#### 希望条件の利用用途

保存した希望条件は、以下で利用します。

* ホーム画面のおすすめ表示
* プレミアムユーザーの比較画面における一致項目ハイライト

一般ユーザーも希望条件を保存できますが、比較画面での一致表示はプレミアムユーザーのみ利用できます。

| --- | --- | --- |

* 希望条件の保存は利用不可

* 問い合わせ送信・園見学予約送信は利用不可
* 園側管理者サイトは利用不可

#### 一般ユーザー

* サポート情報を閲覧可能

### 7-3. バックエンド側の認可

画面側の表示制御だけでなく、バックエンドAPI側でも必ず認可チェックを行います。

特に以下はバックエンド側でも制御します。

* お気に入り登録の上限
* 比較可能な園数
* サポート情報の閲覧権限
* 比較チャートの閲覧権限
* プレミアム状態の判定
* ログインユーザー本人の情報取得
* ログインユーザー本人のプロフィール情報保存・更新
* ログインユーザー本人の希望条件保存・更新
* Stripe Checkoutの利用可否
* Stripe Customer Portalの利用可否
* 保育園管理者APIの利用可否
* 保育園管理者による自園情報のみの取得・編集制限
* 問い合わせ・見学予約を実データ連携する場合の、自園宛データのみの取得制限

プレミアム判定は、Stripeの決済状態をもとに行います。

具体的には `subscriptions.status = ACTIVE` を正とします。

保育園管理者APIでは、Supabase Authのaccess tokenを検証したうえで、`school_admins` にログイン中ユーザーの `userId` が存在するか確認します。

`school_admins` に存在しないユーザーが園管理者APIへアクセスした場合は、`403 Forbidden` を返します。

## 10. データ管理方針

MVPでは園データをseedで登録します。

#32 で検索・比較確認用に seed データを20件へ拡充しています。

### 園情報

* 園ID
* 園名
* エリア
* 住所
* 園種別
* 生活負担
* 時間負担
* 給食・弁当
* 持ち物負担
* 持ち物負担の具体的な内容
* おむつ対応
* 布団対応
* 延長保育利用時間
* 延長保育利用者の目安
* 平日行事の多さ
* 平日行事の具体的な内容
* 保護者会の負担
* 保護者会頻度
* 連絡帳
* 欠席連絡方法
* 園内習い事
* アレルギー対応
* 園の特徴・補足説明
* 経営者名
* 担当者名
* 画像URL

### 条件検索で使用する園データの基準

MVPの条件検索では、以下の値を検索基準として使用します。

| 検索条件 | DB上の値・判定 |
| --- | --- |
| 毎日給食 | `meal_type = SCHOOL_LUNCH` |
| おむつ園処理あり | `diaper_support = "園で廃棄"` |
| 布団負担少なめ | `futon_support = "園で管理"` |
| 保護者会少なめ | `parent_association_level = LOW` |
| 延長保育利用者が多い | `extended_care_usage = "20人以上"` |
| 園内習い事あり | `lessons IS NOT NULL` |
| アレルギー対応あり | `allergy_support IS NOT NULL` |
| 平日行事少なめ | `weekday_events_level = LOW` |

### seed データ登録時の注意

* `lessons` は、園内習い事がある場合のみ内容を登録する
* 園内習い事がない場合、`lessons` は NULL とする
* `lessons` には、年間行事・季節イベント・制作活動などは含めない
* `allergy_support` は、アレルギー対応がある場合のみ内容を登録する
* アレルギー対応がない場合、`allergy_support` は NULL とする
* `extended_care_usage` は、検索基準に合わせて `"20人以上"` / `"10〜20人程度"` / `"10人未満"` のように分類する
* `diaper_support` は、検索条件の「おむつ園処理あり」に該当する場合は `"園で廃棄"` と登録する
* `futon_support` は、検索条件の「布団負担少なめ」に該当する場合は `"園で管理"` と登録する
* 表示用テキスト項目は、比較画面・園詳細画面でそのまま読める文章として登録する

### ユーザー関連

* ユーザーID
* SupabaseユーザーID
* メールアドレス
* お名前
* 郵便番号
* 住所
* 会員区分
* 希望条件
* お気に入り園

### ユーザープロフィール情報

ユーザープロフィール情報は `users` テーブルで管理します。

保存するプロフィール情報は以下です。

* お名前
* 郵便番号
* 住所

郵便番号はハイフンなし7桁で保存します。

郵便番号から住所を取得する処理は、住所検索APIを利用します。

```txt
GET /api/v1/address/search?zipcode=1234567
```

住所検索APIは住所自動入力用であり、DB保存は行いません。

お名前・郵便番号・住所の保存は以下APIで行います。

```txt
PUT /api/v1/users/me
```

### ユーザー希望条件

ユーザー希望条件は `user_preferences` テーブルで管理します。

1ユーザーにつき希望条件は0件または1件とします。

希望条件が未設定の場合、APIでは `preference: null` を返します。

保存する希望条件は以下です。

* 希望する給食・弁当区分
* 希望する持ち物負担レベル
* 希望するおむつ対応
* 希望する布団対応
* 希望する延長保育条件
* 園内習い事ありを希望するか
* アレルギー対応ありを希望するか
* 希望する平日行事負担レベル
* 希望する保護者会負担レベル

保存した希望条件は、ホーム画面のおすすめ表示と、プレミアムユーザー向け比較画面の一致項目ハイライトで利用します。

### 園管理者関連

園管理者アカウントは、ENKATSU運営側が事前に作成・提供します。

保育園管理者の認証はSupabase Authを利用します。

園管理者と管理対象の園は、`school_admins` テーブルで紐づけます。

## 13. 一文要約

ENKATSUは、共働き家庭が園選びで見落としやすい「復職後の保護者負担」を、生活負担・時間負担という軸で検索・比較できるWebアプリケーションです。

未登録ユーザーは園情報を閲覧でき、一般ユーザーはお気に入り3園登録・2園比較・プロフィール情報保存・希望条件保存、プレミアムユーザーはお気に入り無制限・3園比較・比較チャート・希望条件との一致表示・サポート情報閲覧ができます。

さらに、園側管理者サイトにより、保育園管理者がENKATSU運営側から提供されたアカウントでログインし、自園情報を確認・編集できることで、保護者向けだけでなく園側にも価値のあるサービスを目指します。
