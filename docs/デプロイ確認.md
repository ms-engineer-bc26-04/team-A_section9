## Vercel設定

### 環境変数

Vercel の Frontend プロジェクトに、以下の環境変数を設定する。

- NEXT_PUBLIC_API_URL
- NEXT_PUBLIC_SUPABASE_URL
- NEXT_PUBLIC_SUPABASE_ANON_KEY

### 注意点

- NEXT_PUBLIC_API_URL には Backend の Render URL を設定する。
  - https://enkatsu-backend-sg.onrender.com
- NEXT_PUBLIC_SUPABASE_URL には Supabase Project URL を設定する。
- NEXT_PUBLIC_SUPABASE_ANON_KEY は公開キーだが、GitHub Issue や README には実値を記載しない。
- Vercel の Production Branch は staging に設定する。
- Backend URL を変更した場合は、Vercel の NEXT_PUBLIC_API_URL を更新し、Production 環境を再デプロイする。

- REDIS_URL

- STRIPE_WEBHOOK_SECRET

### 注意点

- FRONTEND_URL には Vercel の Frontend URL を設定する。
  - https://enkatsu-frontend.vercel.app
- NODE_ENV は production を設定する。
- STRIPE_SECRET_KEY は Stripe Test Mode の sk_test_... を利用する。
- STRIPE_WEBHOOK_SECRET は Stripe Webhook Endpoint 作成後に取得できる whsec_... を設定する。
- DB接続情報、Redis接続情報、Stripe Secret、Supabase Service Role Key などの実値は公開場所に記載しない。

## Supabase Auth設定

Supabase の Authentication > URL Configuration で、以下を設定する。

### Site URL

- https://enkatsu-frontend.vercel.app

### Redirect URLs

- http://localhost:3000
- http://localhost:3000/**
- https://enkatsu-frontend.vercel.app
- https://enkatsu-frontend.vercel.app/**

### 確認内容

- デプロイ環境で会員登録できること
- デプロイ環境でログインできること
- ログアウトできること
- ログイン後に /api/v1/users/me が 200 OK で取得できること
- 未ログインまたは無効な認証情報では、認証必須APIが 401 Unauthorized を返すこと

## CORS設定

Backend では、以下のOriginを許可する。

- http://localhost:3000
- https://enkatsu-frontend.vercel.app

### 注意点

- デプロイ環境では process.env.FRONTEND_URL を利用して Vercel URL を許可する。
- ローカル開発用に http://localhost:3000 も許可する。
- CORSエラーが出る場合は、Render の FRONTEND_URL と Vercel のデプロイURLが一致しているか確認する。

## トラブルシュート

### ログインできない場合

- Supabase Auth の Site URL / Redirect URLs を確認する。
- Confirm email の設定を確認する。
- Supabase Authentication > Users に対象ユーザーが存在するか確認する。
- ユーザーが confirmed になっているか確認する。
- ブラウザに古いセッションが残っている場合は、サイトデータを削除して再ログインする。

### Backend APIが401になる場合

- Authorization Header に Bearer ${TOKEN} が付いているか確認する。
- TOKENが期限切れでないか確認する。
- SupabaseのProject URLとanon keyの組み合わせが一致しているか確認する。
- RenderのSupabase関連環境変数が正しいか確認する。

### CORSエラーが出る場合

- Render の FRONTEND_URL が https://enkatsu-frontend.vercel.app になっているか確認する。
- Backend のCORS許可Originに http://localhost:3000 と process.env.FRONTEND_URL が含まれているか確認する。
- VercelのProduction URLとSupabase / Render設定のURLが一致しているか確認する。

### Stripe Webhookが失敗する場合

- Stripe Webhook Endpoint URLが正しいか確認する。
- Renderの STRIPE_WEBHOOK_SECRET が、作成したWebhook Endpointの署名シークレットと一致しているか確認する。
- Stripe Test Modeで確認しているか確認する。
- Render LogsでWebhookエンドポイントのエラー内容を確認する。

### Backend URLを変更した場合

- Vercel の NEXT_PUBLIC_API_URL を新しい Backend URL に更新する。
- Render の FRONTEND_URL が Frontend URL と一致しているか確認する。
- Stripe Webhook Endpoint URL を新しい Backend URL に変更する。
- 必要に応じて Vercel を再デプロイする。
- 変更後に /api/v1/schools、/api/v1/users/me、/api/v1/payment/checkout を確認する。
