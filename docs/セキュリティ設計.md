## セキュリティミドルウェア設定

### 目的

既存APIに対して、基本的なセキュリティヘッダー、CORS、Rate Limit を設定し、安全にAPIを利用できる状態にする。

---

### 利用ミドルウェア

バックエンドでは以下のセキュリティ系ミドルウェアを利用する。

| ミドルウェア | 目的 |
| --- | --- |
| helmet | セキュリティヘッダーの付与 |
| cors | フロントエンドからのリクエスト許可 |
| express-rate-limit | 一定時間内の過剰なリクエストを制限 |

---

### Helmet

Helmet により、以下のようなセキュリティヘッダーを付与する。

例：

```txt
X-Frame-Options: SAMEORIGIN
X-Content-Type-Options: nosniff
X-DNS-Prefetch-Control: off
X-Download-Options: noopen
```

---

### CORS

CORSでは、環境変数 `FRONTEND_URL` に設定したフロントエンドURLを許可する。

ローカル開発環境の例：

```env
FRONTEND_URL=http://localhost:3000
```

レスポンスヘッダー例：

```txt
Access-Control-Allow-Origin: http://localhost:3000
```

---

### Rate Limit

開発環境では、React Strict Mode によりAPIが複数回呼ばれることがあるため、Rate Limit の上限を緩める。

| 環境 | 上限 |
| --- | --- |
| development | 1000 |
| production | 100 |

レスポンスヘッダー例：

```txt
X-RateLimit-Limit: 1000
```

---

### 認証が必要なAPIの確認

認証が必要なAPIでは、未認証時に適切なステータスコードを返す。

確認例：

```bash
curl -i "http://localhost:4000/api/v1/users/me"
```

未認証の場合は、`401 Unauthorized` が返ることを確認する。

認証済みで確認する場合は、アクセストークンを付与する。

```bash
curl -i "http://localhost:4000/api/v1/users/me" \
  -H "Authorization: Bearer $TOKEN"
```

認証済みの場合は、`200 OK` とユーザー情報が返ることを確認する。

---

### セキュリティ設定確認コマンド

園一覧APIでヘッダーを確認する。

```bash
curl -i "http://localhost:4000/api/v1/schools"
```

確認する主な項目。

```txt
X-Frame-Options: SAMEORIGIN
X-Content-Type-Options: nosniff
Access-Control-Allow-Origin: http://localhost:3000
X-RateLimit-Limit: 1000
```

---

### 運用ルール

- CORSの許可元は環境変数 `FRONTEND_URL` で管理する
- 本番環境では不要なoriginを許可しない
- 認証が必要なAPIでは、未認証時に `401 Unauthorized` が返ることを確認する
- IssueやPRに確認ログを貼る場合は、Authorizationヘッダーや個人情報を削除する
