# ログ設計書

## Redisキャッシュログ

### 目的

Redisキャッシュの利用状況を確認できるように、園一覧APIで cache hit / cache miss をログ出力する。

また、Redis接続エラー時もログが過剰に出続けないよう、ログ出力頻度を抑制し、Redis停止時・復旧時の状態を確認しやすくする。

---

### 利用ライブラリ

バックエンドでは以下を利用してログを出力する。

- Pino
- pino-http

---

### ログレベル

ログレベルは `LOG_LEVEL` で指定できる。

```env
LOG_LEVEL=debug
```

`LOG_LEVEL` が未設定の場合は、環境ごとに以下のように出し分ける。

| 環境        | ログレベル |
| ----------- | ---------- |
| development | debug      |
| production  | info       |

---

### Redisキャッシュ確認ログ

`GET /api/v1/schools` のキャッシュ確認では、以下のログを出力する。

| ログ               | 内容                                       |
| ------------------ | ------------------------------------------ |
| schools cache miss | Redisにキャッシュがなく、DBから取得した    |
| schools cache hit  | Redisにキャッシュがあり、Redisから取得した |

---

### Redis接続エラーログ

Redis接続に失敗した場合や、Redis接続が切断された場合でも、API提供は継続し、DB取得へフォールバックする。

Redis停止中に同じようなエラーログが大量に出続けると他のログを確認しづらくなるため、Redis接続エラーのログ出力頻度は抑制する。

| ログ例                                                 | 内容                            |
| ------------------------------------------------------ | ------------------------------- |
| Redis connection failed. Continue without Redis cache. | Redis初回接続に失敗した         |
| Redis error. Continue without Redis cache.             | Redis接続中にエラーが発生した   |
| Redis connection closed. Continue without Redis cache. | Redis接続が切断された           |
| Redis connected                                        | Redisに接続、または再接続できた |

---

### Redis読み書き失敗時のログ

Redisの読み取り・書き込みに失敗した場合も、APIレスポンス自体は継続する。

| ログ                                              | 内容                                                    |
| ------------------------------------------------- | ------------------------------------------------------- |
| Redis cache read failed. Fallback to DB.          | Redis読み取りに失敗したため、DB取得へフォールバックした |
| Redis cache write failed. Continue without cache. | Redis書き込みに失敗したが、APIレスポンスは継続した      |

---

### ログ確認コマンド

バックエンドログを確認する。

```bash
docker compose logs backend
```

リアルタイムで確認する。

```bash
docker compose logs -f backend
```

Redisキャッシュ関連ログのみ確認する。

```bash
docker compose logs backend | grep "schools cache"
```

Redis接続関連ログを確認する。

```bash
docker compose logs backend | grep "Redis"
```

---

### ログ出力例

```txt
schools cache miss
schools cache hit
```

実際のPinoログでは、`cacheKey` も出力される。

例：

```txt
"cacheKey":"schools:list","msg":"schools cache miss"
"cacheKey":"schools:list","msg":"schools cache hit"
```

query params がある場合は、以下のようなキャッシュキーになる。

```txt
"cacheKey":"schools:list?area=%E6%B8%8B%E8%B0%B7%E5%8C%BA"
```

Redis読み書き失敗時は、以下のようなログを確認する。

```txt
Redis cache read failed. Fallback to DB.
Redis cache write failed. Continue without cache.
```

Redis復旧後は、以下のようなログを確認する。

```txt
Redis connected
schools cache hit
```

---

### Redis停止時のログ確認

Redisを停止する。

```bash
docker compose stop redis
```

園一覧APIを実行する。

```bash
curl -i "http://localhost:4000/api/v1/schools"
```

以下を確認する。

- `HTTP/1.1 200 OK` が返ること
- Redis停止中でもDB取得へフォールバックすること
- Redis接続エラーのログが過剰に出続けないこと
- Redis読み取り失敗時は `Redis cache read failed. Fallback to DB.` が出ること

---

### Redis復旧後のログ確認

Redisを起動する。

```bash
docker compose up -d redis
```

必要に応じてBackendログを確認する。

```bash
docker compose logs -f backend
```

園一覧APIを複数回実行する。

```bash
curl -i "http://localhost:4000/api/v1/schools"
curl -i "http://localhost:4000/api/v1/schools"
```

以下を確認する。

- Redis復旧後も `GET /api/v1/schools` が `200 OK` を返すこと
- BackendがRedisに再接続できること
- ログに `schools cache hit` が出ること
- Redis復旧後、再びキャッシュが利用できること

既存キャッシュを削除して `cache miss` から `cache hit` になる流れを確認したい場合は、以下を実行する。

```bash
docker compose exec redis redis-cli FLUSHALL
curl -i "http://localhost:4000/api/v1/schools"
curl -i "http://localhost:4000/api/v1/schools"
```

期待するログ。

```txt
schools cache miss
schools cache hit
```

---

### ログ運用ルール

- Redisキャッシュ対象APIを追加した場合は、cache hit / cache miss を確認できるログを出す
- Redis接続失敗時やキャッシュ読み書き失敗時は、DB取得へフォールバックしたことが分かるログを出す
- Redis停止中に同種のエラーログが過剰に出続けないよう、Redis接続エラーのログ出力頻度を抑制する
- Redis復旧後は、再接続できたことやキャッシュが再利用できることをログで確認する
- 本番環境ではアクセストークン、メールアドレス、個人情報、決済情報などをログに出力しない
- IssueやPRにログを貼る場合は、Authorizationヘッダーや個人情報を削除する
