## Redisキャッシュログ

### 目的

Redisキャッシュの利用状況を確認できるように、園一覧APIで cache hit / cache miss をログ出力する。

---

### 利用ライブラリ

バックエンドでは以下を利用してログを出力する。

- Pino
- pino-http

---

### ログレベル

ログレベルは `LOG_LEVEL` で指定できる。

```env
LOG_LEVEL=debug
```

`LOG_LEVEL` が未設定の場合は、環境ごとに以下のように出し分ける。

| 環境 | ログレベル |
| --- | --- |
| development | debug |
| production | info |

---

### Redisキャッシュ確認ログ

`GET /api/v1/schools` のキャッシュ確認では、以下のログを出力する。

| ログ | 内容 |
| --- | --- |
| schools cache miss | Redisにキャッシュがなく、DBから取得した |
| schools cache hit | Redisにキャッシュがあり、Redisから取得した |

---

### ログ確認コマンド

バックエンドログを確認する。

```bash
docker compose logs backend
```

リアルタイムで確認する。

```bash
docker compose logs -f backend
```

Redisキャッシュ関連ログのみ確認する。

```bash
docker compose logs backend | grep "schools cache"
```

---

### ログ出力例

```txt
schools cache miss
schools cache hit
```

実際のPinoログでは、`cacheKey` も出力される。

例：

```txt
"cacheKey":"schools:list","msg":"schools cache miss"
"cacheKey":"schools:list","msg":"schools cache hit"
```

query params がある場合は、以下のようなキャッシュキーになる。

```txt
"cacheKey":"schools:list?area=%E6%B8%8B%E8%B0%B7%E5%8C%BA"
```

---

### ログ運用ルール

- Redisキャッシュ対象APIを追加した場合は、cache hit / cache miss を確認できるログを出す
- Redis接続失敗時やキャッシュ読み書き失敗時は、DB取得へフォールバックしたことが分かるログを出す
- 本番環境ではアクセストークン、メールアドレス、個人情報、決済情報などをログに出力しない
- IssueやPRにログを貼る場合は、Authorizationヘッダーや個人情報を削除する
