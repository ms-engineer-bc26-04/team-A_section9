# 画面設計書：ENKATSU 〜園活を円滑に〜

## 1. 目的

本ドキュメントは、ENKATSU の画面構成・各画面の役割・表示項目・操作内容を整理し、チーム全員が同じ認識で実装を進められるようにするための画面設計書である。

ENKATSU は、共働き家庭・仕事復帰を控えた保護者向けに、保育園・こども園の「復職後の保護者負担」を生活負担・時間負担という2軸で検索・比較できる Web アプリケーションである。

なお、園詳細画面では園側の情報がネガティブなイメージにならないよう、「毎日の準備」「仕事との両立」という表現を使用する。比較画面では保護者目線で負担度合いを比較する目的から、「生活負担」「時間負担」という表現を使用する。

未登録ユーザーは園一覧・園情報を閲覧でき、一般ユーザーはお気に入り登録・2園比較・プロフィール情報の保存・希望条件の保存、プレミアムユーザーはお気に入り無制限登録・3園比較・希望条件との一致表示・サポート情報閲覧ができる。

## 3. 共通設計

### 3.1 共通レイアウト

**全画面共通**

```txt
Header（ロゴ・ハンバーガーメニュー）
↓
Main Content
```

フッターは設置しない。

**ハンバーガーメニューの中身**

未登録ユーザー：

```txt
アカウント
[ 新規会員登録 ] [ ログイン ]

マイ機能
ホーム
お気に入り/比較（ログイン後に利用可）
マイページ（ログイン後に利用可）
プラン・料金確認
```

一般ユーザー：

```txt
ホーム            → /
お気に入り/比較   → /mypage/favorites
マイページ        → /mypage
プラン・料金確認  → /plans
─────────────
ログアウト
```

プレミアムユーザー：

```txt
ホーム            → /
お気に入り/比較   → /mypage/favorites
マイページ        → /mypage
プラン・料金確認  → /plans
─────────────
ログアウト
```

**ハンバーガーメニューの実装方針**

コンポーネントは1つ。ログイン状態・ユーザー区分で中身を出し分ける。

```tsx
{
  !user && <Link href="/register">新規会員登録</Link>;
}
{
  !user && <Link href="/login">ログイン</Link>;
}
{
  user && <Link href="/mypage/favorites">お気に入り/比較</Link>;
}
{
  user && <Link href="/mypage">マイページ</Link>;
}
<Link href="/plans">プラン・料金確認</Link>;
{
  user && <button onClick={logout}>ログアウト</button>;
}
```

### 3.2 共通 UI コンポーネント

| コンポーネント  | 用途                                                                   |
| --------------- | ---------------------------------------------------------------------- |
| Button          | CTA・登録・削除・遷移などの操作ボタン                                  |
| SchoolCard      | 園一覧・お気に入り一覧での園情報表示。カード全体がリンクとして機能する |
| FavoriteButton  | お気に入り登録・解除ボタン（ハートマーク・全ユーザー利用可）           |
| CompareCheckbox | お気に入り一覧での比較対象選択チェックボックス                         |
| SearchBar       | 保育園名・住所検索の入力欄                                             |
| FilterPanel     | 開閉式の「条件で検索」フォーム（毎日給食・おむつ廃棄・布団持参なし等） |
| ProfileForm     | プロフィール編集画面でお名前・郵便番号・住所を保存するフォーム         |
| PreferenceForm  | プロフィール編集画面で希望条件を保存するフォーム                       |
| Modal           | 確認ダイアログ・プレミアム誘導など                                     |
| Toast           | 操作フィードバック（成功・エラー・警告）                               |
| Skeleton        | データ取得中のプレースホルダー                                         |
| EmptyState      | データが存在しない場合の表示                                           |
| ErrorMessage    | 入力エラー・API エラーの表示                                           |
| Loading         | ページ・API 取得中のスピナー                                           |
| LockOverlay     | プレミアム限定機能の制限表示（テキスト付きオーバーレイ）               |
| MatchBadge      | 希望条件との一致表示（プレミアムのみ）                                 |

### 3.3 エラー表示方針

- 入力値に誤りがある場合は、フォーム項目の直下にエラーメッセージを表示する
- API 通信に失敗した場合は、画面上部または操作付近に Toast / エラーバナーを表示する
- 未登録ユーザーが認証必須画面にアクセスした場合は `/login` へ遷移する
- 一般ユーザーがプレミアム限定機能にアクセスした場合は LockOverlay を表示し `/plans` へ誘導する
- 存在しない URL へアクセスした場合は 404 ページへ遷移する
- 検索結果が0件の場合は「条件に合う園が見つかりませんでした」を表示する
- プロフィール情報・希望条件の保存に失敗した場合は Toast または ErrorMessage でエラーを表示する

### 3.4 ローディング表示方針

- API からデータ取得中は Skeleton コンポーネントを表示する
- ボタン操作中はボタン内スピナー + disabled 状態にして二重送信を防ぐ
- ページ遷移中はローディング画面を表示する
- データが存在しない場合は EmptyState でメッセージを表示する

## 4. 画面詳細

### 4.1 ホーム画面（未登録ユーザー）

**URL**

`/`

**目的**

未登録ユーザーが ENKATSU のサービス概要を把握し、保育園名・住所または条件で検索、または園一覧から園を探せるようにする。

**表示項目**

| 項目                 | 内容                                                                                                                             |
| -------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| キャッチコピー       | サービスの価値を一言で表す                                                                                                       |
| サービス説明         | 生活負担・時間負担という2軸での園比較サービスであることを説明する                                                                |
| メイン検索フォーム   | 保育園名・住所で検索できる                                                                                                       |
| 条件で検索（開閉式） | 毎日給食／おむつ廃棄／布団持参なし／延長保育の利用時間〜19時まで／平日行事なし／保護者会なし／園内習い事あり／アレルギー対応あり |
| 園一覧               | SchoolCard（タグ付き）を一覧表示する                                                                                             |

**操作**

- 保育園名・住所を入力して検索する → `/schools/search` へ遷移
- 「条件で検索」を開いて条件を選択し検索する → `/schools/search` へ遷移（条件をクエリに付与）
- SchoolCard（カード全体）をクリックすると `/schools/[id]` へ遷移する
- FavoriteButton（ハート）をクリックするとログイン誘導モーダルを表示する

---

### 4.2 ホーム画面（一般・プレミアムユーザー）

**URL**

`/`

**目的**

ログイン済みユーザーが保育園名・住所または条件で検索、またはおすすめの園を探せるようにする。

**利用 API**

| メソッド | エンドポイント | 内容                                                 |
| -------- | -------------- | ---------------------------------------------------- |
| GET      | `/users/me`    | ログインユーザー情報・プロフィール情報・希望条件取得 |
| GET      | `/schools`     | 園一覧・検索結果・おすすめ表示取得                   |

**表示項目**

| 項目                 | 内容                                                                                                                             |
| -------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| キャッチコピー       | サービスの価値を一言で表す                                                                                                       |
| メイン検索フォーム   | 保育園名・住所で検索できる                                                                                                       |
| 条件で検索（開閉式） | 毎日給食／おむつ廃棄／布団持参なし／延長保育の利用時間〜19時まで／平日行事なし／保護者会なし／園内習い事あり／アレルギー対応あり |
| おすすめの園一覧     | おすすめロジックに基づいた SchoolCard（タグ付き）を表示する                                                                      |

**おすすめ表示ロジック**

```txt
ステップ1：プロフィール情報・希望条件を確認
GET /users/me の address と preference を確認する

ステップ2：住所・希望条件で並び替え
・住所設定済み → 同じエリアの園を優先
・希望条件設定済み → 一致度が高い順に表示
・住所・希望条件未設定 → 通常の園一覧または既存のおすすめロジックで表示
```

**プロフィール情報・希望条件の扱い**

- プロフィール情報は `GET /api/v1/users/me` の `name` / `postalCode` / `address` から取得する
- 希望条件は `GET /api/v1/users/me` の `preference` から取得する
- `address: null` の場合は住所未設定として扱う
- `preference: null` の場合は希望条件未設定として扱う
- 希望条件は `user_preferences` に保存された値を利用する
- おすすめ順ロジックでは、後続Issueで住所・希望条件との一致度を利用する

**Redisキャッシュ**

ホーム画面のおすすめ表示・園一覧取得では、Redisキャッシュを利用する。

- 園一覧の元データをキャッシュする
- 検索条件・並び順ごとにキャッシュキーを分ける
- ログインユーザーごとに変わるお気に入り状態・会員状態・プロフィール情報・希望条件は、キャッシュ対象と分けて扱う

**操作**

- 保育園名・住所を入力して検索する → `/schools/search` へ遷移
- 「条件で検索」を開いて条件を選択し検索する → `/schools/search` へ遷移（条件をクエリに付与）
- SchoolCard（カード全体）をクリックすると `/schools/[id]` へ遷移する
- FavoriteButton（ハート）でお気に入り登録・解除する

### 4.3 検索結果画面

**URL**

`/schools/search`

**目的**

全ユーザーが保育園名・住所・条件で絞り込んだ結果を一覧表示し、詳細画面へ進めるようにする。画面上部にはメイン検索バーと条件で検索を表示し、再検索もこの画面内で行える。

**利用 API**

| メソッド | エンドポイント | 内容                                 |
| -------- | -------------- | ------------------------------------ |
| GET      | `/schools`     | 検索結果取得（Redis キャッシュ必須） |

**検索条件**

| 区分                 | 条件                                                                                                                             |
| -------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| メイン検索           | 保育園名・住所                                                                                                                   |
| 条件で検索（開閉式） | 毎日給食／おむつ廃棄／布団持参なし／延長保育の利用時間〜19時まで／平日行事なし／保護者会なし／園内習い事あり／アレルギー対応あり |

**表示項目（SchoolCard）**

| 項目           | 内容                                                                                   |
| -------------- | -------------------------------------------------------------------------------------- |
| 写真           | 園の画像                                                                               |
| 園名           | 園の名称                                                                               |
| 住所           | 所在地                                                                                 |
| 電話番号       | 園の電話番号                                                                           |
| タグ           | 検索条件に該当するもののみタグ表示（例：「保育園」「毎日給食」「園内習い事あり」など） |
| FavoriteButton | お気に入り登録・解除（ハートマーク・全ユーザー利用可）                                 |

SchoolCard はカード全体がリンクとして機能し、クリックすると `/schools/[id]` へ遷移する（詳細ボタンは設置しない）。

**Redisキャッシュ**

検索結果画面では、園一覧・検索結果の取得にRedisキャッシュを利用する。

- `keyword`
- `area`
- 条件検索項目
- `sort`
- `limit`
- `offset`

などをもとにキャッシュキーを生成する。

ただし、`isFavorited` などログインユーザーごとに変わる情報は、キャッシュされた園データとは分けて付与する。

**お気に入り件数制限**

| ユーザー区分       | 上限                             |
| ------------------ | -------------------------------- |
| 未登録ユーザー     | 利用不可（ログイン誘導モーダル） |
| 一般ユーザー       | 5件まで                          |
| プレミアムユーザー | 無制限                           |

上限に達した状態でハートをクリックした場合、Toast で「お気に入りは5件まで登録できます。プレミアムで無制限に」と表示し `/plans` へ誘導する。

**空状態**

```txt

```

### 4.4 園詳細画面

**URL**

`/schools/[id]`

**目的**

全ユーザーが個別の園の基本情報・毎日の準備・仕事との両立を閲覧できるようにする。サポート情報はプレミアム限定とする。園詳細画面では園側の情報がネガティブなイメージにならないよう「毎日の準備」「仕事との両立」という表現を使用する（比較画面では「生活負担」「時間負担」を使用）。

**利用 API**

| メソッド | エンドポイント | 内容       |
| -------- | -------------- | ---------- |
| GET      | `/schools/:id` | 園詳細取得 |

**表示項目**

| カテゴリ     | 項目                                                  | 未登録・一般ユーザー     | プレミアムユーザー |
| ------------ | ----------------------------------------------------- | ------------------------ | ------------------ |
| 基本情報     | 園名・住所・電話番号・園種別                          | ✅                       | ✅                 |
| タグ         | 検索条件に該当する特徴タグ                            | ✅                       | ✅                 |
| 毎日の準備   | 給食・弁当 / 持ち物 / おむつ対応 / 布団対応           | ✅                       | ✅                 |

### 4.11 プロフィール編集画面

**URL**

`/mypage/edit`

**目的**

ログイン済みユーザーが、自分のお名前・郵便番号・住所・希望条件を保存・更新できるようにする。

お名前・郵便番号・住所はマイページ上のプロフィール情報として利用する。
郵便番号7桁入力時には住所検索APIを利用して住所を自動入力する。

希望条件は、ホーム画面のおすすめ表示・プレミアムユーザーの比較画面での一致表示に使用される。

**利用 API**

| メソッド | エンドポイント                    | 内容                                                 |
| -------- | --------------------------------- | ---------------------------------------------------- |
| GET      | `/users/me`                       | ログインユーザー情報・プロフィール情報・希望条件取得 |
| PUT      | `/users/me`                       | お名前・郵便番号・住所の保存・更新                   |
| PATCH    | `/users/me/preferences`           | ユーザー希望条件の保存・更新                         |
| GET      | `/address/search?zipcode=1234567` | 郵便番号から住所を検索                               |

**初期表示**

プロフィール編集画面の初期表示では、`GET /api/v1/users/me` で取得したプロフィール情報と `preference` を利用する。

- `name` が存在する場合は、お名前入力欄に反映する
- `postalCode` が存在する場合は、郵便番号入力欄に反映する
- `address` が存在する場合は、住所入力欄に反映する
- `name` / `postalCode` / `address` が `null` の場合は、未入力の状態で表示する
- `preference` が `null` の場合は、希望条件未設定としてフォームを未選択の状態で表示する
- `preference` が存在する場合は、保存済みの希望条件をフォームに反映する

**表示項目**

| 項目       | 内容                                                                                                          |
| ---------- | ------------------------------------------------------------------------------------------------------------- |
| お名前     | ユーザーの表示名・お名前を入力する                                                                            |
| 郵便番号   | ハイフンなし7桁で入力する                                                                                     |
| 住所       | 郵便番号検索APIで自動入力、または手入力する                                                                   |
| 希望条件   | 生活負担・時間負担・補助情報に関する希望をチェックボックスまたは選択式で設定する                              |

| 住所     | `address`    | `users.address`     | 1文字以上255文字以内 |

**住所自動入力**

郵便番号7桁入力時に `GET /api/v1/address/search?zipcode=1234567` を実行し、取得した住所を住所欄に自動入力する。

住所検索APIは住所自動入力用であり、DB保存は行わない。
住所の保存は `PUT /api/v1/users/me` で行う。

**希望条件**

- 平日行事が少ない
- 保護者会が少ない

#### 補助情報

## 6. 認証・認可による画面制御

| 画面                       | 未登録                           | 一般                                   | プレミアム                             |
| -------------------------- | -------------------------------- | -------------------------------------- | -------------------------------------- |
| `/`                        | ✅                               | ✅                                     | ✅                                     |
| `/schools/search`          | ✅                               | ✅                                     | ✅                                     |
| `/schools/[id]`            | ✅（サポート情報はオーバーレイ） | ✅（サポート情報はオーバーレイ）       | ✅（全情報閲覧可）                     |
| `/login`                   | ✅                               | リダイレクト（`/`）                    | リダイレクト（`/`）                    |
| `/register`                | ✅                               | リダイレクト（`/`）                    | リダイレクト（`/`）                    |
| `/plans`                   | ✅                               | ✅（新規会員登録はグレーアウト）       | ✅（両ボタングレーアウト）             |
| `/mypage/favorites`        | ❌ → `/login`                    | ✅（5件・2園比較）                     | ✅（無制限・3園比較）                  |
| `/compare`                 | ❌ → `/login`                    | ✅（一致表示なし）                     | ✅（一致表示あり）                     |
| `/mypage`                  | ❌ → `/login`                    | ✅（プレミアム誘導表示）               | ✅（プレミアム状態・解約導線）         |
| `/mypage/edit`             | ❌ → `/login`                    | ✅（プロフィール情報・希望条件保存可） | ✅（プロフィール情報・希望条件保存可） |
| `/payment/complete`        | ❌ → `/login`                    | ✅                                     | ✅                                     |
| `/payment/cancel-complete` | ❌ → `/login`                    | ✅                                     | ✅                                     |

**制御方針**

- 未ログインユーザーが認証必須画面へアクセスした場合は `/login` へ遷移する
- 一般ユーザーがプレミアム限定機能にアクセスした場合は LockOverlay を表示し `/plans` へ誘導する
- 園詳細画面のサポート情報は、未登録ユーザー・一般ユーザーには項目名のみを表示し、値の部分にスモーク（ぼかし）をかけた上に「プレミアムユーザーに登録すれば閲覧可能」というテキスト付きのオーバーレイを重ねて表示する
- サポート情報のロック表示をタップした場合、未登録ユーザーは `/register`、一般ユーザーは `/plans` へ誘導する
- 画面側のルートガードに加え、バックエンド API 側でも必ず認可チェックを行う
- プレミアム判定は `subscriptions.status = ACTIVE` を正とする
- お気に入り件数は一般ユーザー5件・プレミアム無制限とし、バックエンド側でも制限チェックを行う
- `/plans` のボタン表示制御（グレーアウト）はログイン状態・会員区分をもとにフロントエンドで判定する
- `/payment/cancel-complete` は Stripe Customer Portal からの戻り先であるため、ログイン済みユーザーであれば一般ユーザー・プレミアムユーザーのどちらも表示可能とする
- `/mypage/edit` のプロフィール情報・希望条件保存は、一般ユーザー・プレミアムユーザーのどちらも利用可能とする
- 希望条件との一致表示は、プレミアムユーザーのみ利用可能とする

## 9. 備考

本画面設計書は、チーム開発時の認識合わせを目的とした初期ドキュメントである。

実装中に画面構成や仕様が変更になった場合は、Issue または PR コメントに理由を残し、必要に応じて本ドキュメントを更新する。

画面デザインは MVP では細かい装飾よりも、操作しやすさ・認証認可の分かりやすさ・ユーザー区分ごとの機能制限の明確さを優先する。

**セクション名の使い分けについて**

園詳細画面では「毎日の準備」「仕事との両立」という表現を使用する。これは園側の情報がネガティブなイメージにならないようにするためである。比較画面では保護者目線で負担度合いを比較する目的から「生活負担」「時間負担」を使用する。

**プロフィール編集画面について**

現時点のMVP実装では、プロフィール編集画面でお名前・郵便番号・住所・希望条件を保存・更新する。

お名前・郵便番号・住所は `PUT /api/v1/users/me` で保存する。
希望条件は `PATCH /api/v1/users/me/preferences` で保存する。

郵便番号から住所を取得する処理は `GET /api/v1/address/search?zipcode=1234567` を利用する。
住所検索APIは住所自動入力用であり、DB保存は行わない。
